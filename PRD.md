# Product Requirements Document (PRD): Ragio-Lab

> What Ragio-Lab must do, derived from [README.md](README.md) and [DESIGN.md](DESIGN.md). Architecture detail lives in DESIGN.md; open work is tracked in [GitHub Issues](https://github.com/bamr87/ragio-ai/issues).

## 1. Overview

Ragio-Lab makes the entire Radiolab archive (~700+ episodes, ~500–600 hours of audio) available as grounded context for a local LLM, so analytical, review and creative questions are answered with citations down to the second and a playable clip.

| Area | Status |
| --- | --- |
| In scope (shipped, v0.1) | RSS catalog, MP3 download, local Whisper transcription, windowing, hybrid Qdrant index, episode summaries, cited RAG answers (CLI + API + SSE), clips, deep listen, retrieval eval, single-page web UI |
| Planned | Episode-level routing, creative propagation modes, knowledge graph, diarization (DESIGN.md § 8–9) |
| Out of scope | Multi-user auth, cloud deployment, redistributing audio, clips or transcripts |

## 2. Users

One researcher running the whole stack on a single machine (Apple Silicon Mac or a Linux/NVIDIA box).

## 3. Goals

- Every answer is grounded in retrieved evidence and cites episode + timestamp.
- Every pipeline stage is local, idempotent and resumable.
- Retrieval quality is measured, not guessed (hit@k against golden questions).

## 4. Requirements

### Functional

- FR1: Parse the Radiolab RSS feed into a SQLite catalog of episodes with per-episode pipeline status (`catalogued → downloaded → transcribed → chunked → indexed | failed`).
- FR2: Download episode audio locally, resumably, with an optional `--limit`.
- FR3: Transcribe audio locally with Whisper (`faster-whisper` or `mlx-whisper`), producing segments with start/end and word timestamps, cached as JSON, with VAD to skip music beds.
- FR4: Merge Whisper segments into retrieval windows (~220 words, ≤120 s, 1-segment overlap) stored in SQLite.
- FR5: Embed windows into Qdrant with deterministic point ids (`uuid5(episode_id:idx)`) and a payload sufficient to jump to the moment; re-indexing upserts.
- FR6: Build an optional episode-summary collection (summary, themes, people) for "which episodes are about X?" questions.
- FR7: Answer questions by hybrid (dense + BM25) retrieval, ±1 neighbor expansion, grouping by episode, and an Ollama LLM prompt that cites evidence labels; available from the CLI, as JSON and as an SSE stream.
- FR8: Provide retrieval-only search grouped by episode.
- FR9: Serve audio clips for a cited range (ffmpeg cut, cached, ≤10 min).
- FR10: Answer audio-native questions about a clip (≤3 min) through an optional audio model (Qwen2-Audio via OpenAI-compatible endpoint or transformers).
- FR11: Measure retrieval hit@1/3/5 against `eval/questions.jsonl`.
- FR12: Offer a browser UI to browse episodes and timestamped transcripts, ask questions, see sources and play clips.
- FR13: Report pipeline progress (episodes per stage).

### Roadmap (planned)

- FR14: Phase 1: index the full archive and reach eval hit@5 ≥ 0.85 on eval/questions.jsonl
- FR15: Phase 2: route questions to candidate episodes via the summary collection before chunk retrieval
- FR16: Phase 3: GPU deep-listen mode re-transcribing cited ranges with a larger Whisper model
- FR17: Phase 4: creative modes and an episode/people/themes knowledge graph
- FR18: Phase 5: speaker diarization attached to transcript segments
- FR19: Export pipeline metrics and traces over OTLP to bamr87/fleet-observe

### Non-functional

- NFR1: Fully local — the only network calls are the RSS feed and MP3 downloads.
- NFR2: Every stage is idempotent and resumable.
- NFR3: Configuration is environment variables with defaults in `ragio/config.py`; no secrets in the repo.
- NFR4: Generated answers never go beyond the evidence and always show sources; creative output never reproduces transcript text at length.
- NFR5: Personal research use only: audio, transcripts and clips are never committed or redistributed.
- NFR6: The LLM prompt caps evidence size to avoid context overflow.

## 5. Roadmap

DESIGN.md § 8: phase 1 full archive indexed with eval hit@5 ≥ 0.85; phase 2 episode routing; phase 3 GPU deep listen; phase 4 creative modes + knowledge graph; phase 5 diarization.
